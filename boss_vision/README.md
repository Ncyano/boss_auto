## 坐标是怎么来的

全部以**识别到的「打招呼」按钮**为锚点算偏移，不用屏幕绝对坐标：

| 关系 | 实测值（2560×1400 窗口） |
|---|---|
| 列表「打招呼」按钮 | 92×32 px，每张卡片一个，垂直节距 184 px |
| 卡片区域 | 右缘 = 按钮右缘 + 38；宽 1212；高 172；按钮中心比卡片顶低 39 |
| 点开简历的落点 | 按钮左移 560、下移 40（卡片正文中部） |
| 简历弹窗「打招呼」大按钮 | 285×40，可作为"弹窗已打开"的标志 |
| 弹窗关闭 ✕ | 大按钮右缘 +14、顶 -84 → (1908, 168) |

所以窗口移动/换位置不影响；但**浏览器缩放比例变了要重新标定**（Ctrl+0 保持 100%）。

## 二元结论口径（v0.2 起）

筛选结论只有两个值：**合适 / 不合适**，不再输出「待复核」。

核实不了的一律按**不合适**处理，并把原因写清楚（便于补采后重判）：

| 情况 | 结论 | 原因示例 |
|---|---|---|
| 采集不完整（缺公司名/教育截断） | 不合适 | 采集不完整：第一段教育缺学校 |
| 学历层次/学习形式未识别 | 不合适 | 无法核实学历：学历字段缺识别 |
| 年龄未识别（A01 无法执行） | 不合适 | 无法核实：年龄未识别 |
| 校名未命中名单（E03） | 不合适 | 无法核实：校名 XX 未命中指定名单 |
| 工作经历模型未接入/调用失败 | 不合适 | 未接入判断模型 / 调用失败 |

「需复核」「复核原因」列仍然保留，作为**数据质量诊断**，但不再是一档结论。

## 第二轮：去重冲突 / 尺度自适应 / 完整导出


### 1. 冲突不再被静默合并

| 情况 | 处理 |
|---|---|
| 同一时间段、两家不同公司 | **不合并**，各自保留，记「跨屏冲突」 |
| 同公司同时间、职位不一致 | 保留先读到的值，记「职位不一致」 |
| 侧栏与正文同期不同单位 | 只记冲突，**不写摘要条目** |

冲突数写进 CSV 的 `冲突数` 列，并计入复核原因（`N 处跨屏冲突`）。

### 2. 尺度自适应（换分辨率/DPI 不再错位）

所有几何偏移原本是 2560×1400、100% 缩放的实测值，现在改为**按检测到的按钮宽度反推缩放系数**：

```python
k = scale_of(button.w, REF_BUTTON_W)     # 92px 为基准
card_w = 1212 * k ; 点击点 = (button.x - 560k, button.cy + 40k)
```

`card_for` / `click_into_resume` / `progress_icon` / `panel_band` 全部按 k 缩放。
实测 1.25x / 1.5x / 2x 时卡片宽度同比变化（误差 < 3%）。

### 3. 完整导出：JSON 是唯一数据源，CSV 只是视图

- **JSON 不再被错字表覆盖**：`textfix` 只在导出 CSV / 筛选时套用，原始文本永远可追溯；
- **模型输入不限段数**：`screening.work_text()` 按 CSV 里实际存在的「第 N 家」列拼，不截断 10 段；
- **逐屏截图**：只对「需复核」的候选人落盘到 `runs/<stamp>-shots/`，正常记录不占空间；
- 每条经历带 `screens`（来源屏号），CSV 有 `采集完成 / 屏数 / 读到章节 / 冲突数 / 需复核 / 复核原因`。

## 采集质量与跨屏解析（重构）


### 1. 采集闸门：不合格的数据不进模型

`tools\\screen_resumes.py` 判定顺序改为：**采集质量 -> 学历规则 -> 工作经历门槛 -> 模型评分**。

任一项不满足就输出 **「采集待复核」**，不判学历、不调模型、不打招呼：

- 简历没成功打开
- 带「需复核」标记（缺公司名/缺职位/教育未读到等）
- 工作经历章节没读到（区别于"读到了但确实 0 条"）
- 第一段教育的学校或学历缺识别

「工作经历 0 条」只有在**章节确实读到**时才交给业务规则判不合格；章节没读到属于采集问题。

### 2. 跨屏解析（stream_parse.py）

不再每屏独立重新解析，改由 `StreamParser` 维护状态：

```
current_section  当前章节        current_entry  正在读的条目        tail  跨屏续行
```

- 遇到新章节标题 → 结束当前条目
- 遇到新经历表头 → 新建条目
- 没有表头的后续文本 → 追加到当前条目（上一行没写完就拼接续行）
- 同一段经历在下一屏再次出现 → **合并缺失字段 + 追加新增职责**，不整体丢弃
- 公司/职位/时间分三行、或公司丨职位一行、或表头被裁只剩时间，三种版式都能还原

去重改成分层：条目内文本去重 + 相邻屏重叠去重；**不同公司的相同职责不会被删**。
日期相同但公司不同 = 两段经历，保留。

### 3. 采集完成状态

`ReadResult.stopped_reason` 三分类，不再用"教育标题后出现文本"当完成依据：

| 状态 | 含义 | 后续 |
|---|---|---|
| `读取完成（已读到教育经历）` | 第一段教育已完整读到 | 进入筛选 |
| `页面未移动（…）` | 滚不动了，判断到底 | 看是否读到教育 |
| `达到滚动上限 N 屏` | 采集未完成 | 进复核 |

回顶也改为**验证式**：滚动后比对画面，变化 < 0.5 才认定到顶（最多试 2 次）。

### 4. 侧栏降级为辅助证据

- 不再因为机构名含「大学/学院」就归入教育经历，只按时间形态（只有年份）判断
- 不再只按日期匹配对应关系，必须公司名相似（前缀/相似度）
- 侧栏补入的条目带 `summary_only: true` + 备注「侧栏摘要：只有单位/职位/时间，正文未读取」

### 5. 三层数据都保留

| 层 | 落点 |
|---|---|
| 原始层 | `*-results.json` 的 `ocr_lines`（每屏每行的文本/置信度/坐标/屏号）、`-resume-N.txt` |
| 结构化层 | `work[]` / `education[]`，每条带 `screens`（来源屏）；`school_raw` 保留 OCR 原名，`school` 是名单校正后的名字 |
| 业务层 | CSV 的 `采集完成` / `屏数` / `读到章节` / `需复核` / `复核原因` |

## 读简历：先回顶部 + 侧栏交叉校验


打开弹窗后读简历时，做两件事：

1. **先滚回顶部再读** —— 否则第一条经历的表头可能正好被裁在可视区上方（实测张锦敏就丢了整段公司名）。滚一下（向上 5 格）再开始逐屏读。
2. **读右侧「经历概览」做交叉校验** —— 那边是「公司 + 时间段」一行、「职位 + 时长」一行的干净列表：
   - 主区域缺的**职位**，按时间段从侧栏补；
   - 主区域缺的**公司名**，从侧栏补（侧栏被省略号截断的 `…`/`...` 不写，只计数）；
   - 主区域**整段漏掉**的，从侧栏补入（标 `source=sidebar`）；
   - 学校类条目（含学院/大学/学校）自动归到教育经历。

日志会打印：`侧栏经历概览：12 段` / `侧栏合并：补 2 项，新增 4 段，截断 4 条`。

侧栏相关代码：`resume_reader.sidebar_band / parse_sidebar_items / merge_sidebar / read_sidebar`，
自测：`python boss_vision\test_sidebar.py`（含真实截图的 OCR 校验）。

## 工作经历解析规则（2026-10-21 加强）


BOSS 简历排版不固定，同一个"公司 / 职位 / 时间"可能排成三种样子，解析时统一合成一条：

| 版式 | 处理 |
|---|---|
| `公司丨职位` + 下一行 `时间` | 直接取词 |
| `公司` / `职位` / `时间` 各占一行 | 时间行若前面的行**没有机构后缀**、再前面一行**有**，就把三行合成 `公司丨职位 时间` |
| `公司` + `时间`（无职位） | 公司名照取，职位留空 |

配套的几条保护：

- **职位词识别**：无机构后缀却含 `运营/拍摄/新媒体/店长/中控/客服…` 的，判为职位，不写成公司名；
- **拆分兜底**：`网店店长` 被切成「网店店」+「长」时，整体留作职位；
- **城市名兜底**：`福州` 这种只有城市没公司名的，判公司缺失，不写脏数据；
- **按时间排序**：拼接顺序错乱时，按「是否至今 + 结束年月」倒序纠正，保证第 1 家就是最近一段；
- **错字表**：`有效公司 → 有限公司`、`暑署托班 → 暑托班` 已进 `data\corrections.json`。

## OCR 错字修正表


OCR 偶尔会认错字或重复字（实测：`省直职工子女暑托班` 被识别成 `暑署托班`）。这类错误没有通用规则，所以做成一张**随时可编辑**的对照表：

`boss_vision\corrections.json`

```json
{
  "暑署托班": "暑托班",
  "有限公司Q": "有限公司"
}
```

- 左边写识别错的串，右边写正确的；**长串优先替换**，不会互相拆坏；
- 生效范围：写 `results.json` 时、生成 `summary.csv` 时、`backfill_names.py` 回填历史时；
- 加完不用改代码，重跑/重新导出即可：

```powershell
.\.venv\Scripts\python.exe boss_vision\backfill_names.py --force   # 修历史 json
.\.venv\Scripts\python.exe boss_vision\export_csv.py               # 重新导出 csv
```

## 每次采集自动产出什么

跑一轮（无论正常结束、点停止还是 Ctrl+C）都会在 `boss_vision\runs\` 落下三份：

| 文件 | 内容 |
|---|---|
| `<时间>-results.json` | 结构化结果（姓名/工作经历/教育经历/分节全文） |
| `<时间>-summary.csv` | **汇总表，含「最近一段工作内容」「全部工作经历」两列** |
| `<时间>-resume-N.txt` | 每位候选人的简历全文 |
| `<时间>-console.log` | 控制台日志（含 stderr 与 traceback） |

CSV 在结束时统一生成一次（中途只增量写 json，避免反复刷盘）。

## 当天汇总表（按日期命名，自动累计）

每次采集结束除了每轮的 `<时间>-summary.csv`，还会自动更新**当天那张表**：

```
runs\2026-10-21.csv        ← 一天一张，跑几次都在同一张表里累计
```

- 文件名 = 采集当天的日期（`YYYY-MM-DD.csv`）；
- 每次都**并入**已有内容，不会覆盖之前采到的；
- 去重键 = `姓名 + 第1家公司 + 第1家起止`（同一个人重复采到只留最新一条）；
- **序号在当天表里连续重排（1..N）**：每轮采集的 `index` 都从 1 开始，合并后会重新编号，不会出现重复的 1、2、3；
- **跨天自动换表**：第二天采集时直接新建 `YYYY-MM-DD.csv`，序号从 1 开始，前一天的记录仍留在前一天那张表里；
- 想用历史 results.json 重建当天这张表：

```powershell
.\.venv\Scripts\python.exe boss_vision\export_csv.py --today
```

## CSV 的列（工作经历按第 1~10 家展开）


工作经历**不再只写"最近一段"**，而是按简历顺序展开成 10 个槽位（`MAX_COMPANIES = 10`）：

```
序号 姓名 已打开 工作经历条数
第1家公司 第1家职位 第1家起止 第1家工作内容
第2家公司 第2家职位 第2家起止 第2家工作内容
…（一直到第10家，共 40 列）
教育条数 学校 专业 学历 教育起止 滚屏数 停止原因 间隔(秒)
```

- **第1家 = 简历里从上往下第一条**（通常就是最近在职的那段）；
- 不足 10 家的槽位留空；
- 「工作内容」= 该段经历下面的描述行 + 标签，多条用「；」连接；
- 全套 52 列；控制台表格只显示精简列（第1家公司/职位 + 教育 + 状态），**明细都在 CSV 里**。

## 节奏控制：候选人之间的随机间隔

每处理完一个候选人，等 **15~25 秒随机** 再进下一个（`--min-gap` / `--max-gap` 可调，默认 15/25）：

```
已回到列表
等待 18.4 秒再处理下一个（15~25s 随机）
```

- 计时起点 = 上一个候选人的动作全部结束之后（当前是"读完 + 关闭弹窗"）；
- **打招呼实装后**：把 greet 插进这套动作里，起点自然变成"打完招呼之后"，`wait_between_candidates()` 不用改；
- 最后一个候选人不等待；dry-run 不等待；
- 实际等待时长会写进 `results.json` 的 `gap_before_next`。

## 跳过规则：文字淡化的卡片

同事已经沟通过的候选人，BOSS 会把卡片文字(和同事沟通进度一起)变淡。规则是**不点击、直接跳过**。

有**两条并列判据**，命中任一条就跳过：

1. **文字淡化**（`vision.is_contacted()`）—— 量卡片文字区的"墨迹深浅"；
2. **存在「同事沟通进度」人像图标**（`vision.progress_icon()`）—— 用模板匹配 `assets\icon_person.png`，得分 ≥0.80 判为存在。

   ⚠️ 这一排图标可能是 **1~2 个**（饼图 / 人像）且**右对齐**：只有饼图时它会挪到人像的位置，两者都是青色、像素数相同。所以**不能数青色像素**，必须比形状。实测得分：有人像图标 = 1.000，只有饼图 = 0.464。

文字淡化的两个指标：

| 指标 | 淡化卡 | 正常卡 |
|---|---|---|
| 深色像素占比（亮度 <100） | 0.04 ~ 0.06 | 0.23 ~ 0.31 |
| 文字 p10 亮度 | ≥ 121 | 41 |

阈值：`dark_ratio < 0.12` 或 `p10 > 100`（`vision.DIM_DARK_RATIO` / `vision.DIM_P10`），实测空隙很大。

> 若哪天 BOSS 改了图标样式或你把浏览器缩放改离 100%，重新生成模板即可：`python calibrate_icon.py --image <截图> --write`。

另外，**被屏幕底边截断的卡片**（`card.y + 172 > 窗口高` 或按钮高度异常）也会跳过，避免点空。

`driver.py plan` 会把两者分别标成 `已沟通(淡化)` / `被截断`，并在标注图里画灰框、不画落点。

**整屏都跳过时的处理**：如果当前屏幕上的卡片**全部**要跳过（比如 8 张都是同事已沟通），不做无谓滚动，而是**刷新页面（F5）换一批候选人**；刷新后重新识别，最多刷 `--max-refresh` 次（默认 3），用尽就停下并报告。刷新前后卡片位置完全没变时会打印警告（说明刷新没生效，通常是注入被拦或页面没重载）。

## 跳过规则：内嵌「热搜牛人推荐」块

列表中间会插一段淡青色的推荐块（标题「热搜牛人推荐」+ 一位牛人 + 查看更多）。**整块都不点**：

- 检测：`vision.find_special_blocks()` 找那块淡青色标题带（RGB≈236,249,249，宽>600、高>15）；
- 定界：`vision.block_zones()` 把标题带扩展成整块区域 —— 从标题带顶部，到**下一张正常卡片的上沿**（块体是近白色，靠颜色判断下边界不可靠）；
- 跳过：任何卡片中心落进这个区域，就记 `热搜牛人推荐` 并跳过；标注图里会画品红框 + `special block -> skip`。

注意：这个规则依赖"淡青色标题带"这个视觉特征。若 BOSS 换成别的配色/样式，需要调 `vision.py` 里的 `SPECIAL_BG_MIN` 门槛。

## 读简历：滚动 + 逐屏拼接

`resume_reader.py` 负责把整份简历读完（教育经历经常在首屏以下），`extract.py` 负责把 OCR 行变成结构化条目。

### 结构化提取（extract.py）

输出形状：

```json
{
  "work": [
    {"company": "福建飞鸟传媒有限公司", "title": "后期剪辑·后期部",
     "period": "2023.06-至今", "employment": "",
     "descriptions": ["主要负责公司项目的后期制作…"], "tags": ["Premiere", "视频剪辑"]}
  ],
  "education": [
    {"school": "岳阳学院", "major": "广告", "degree": "本科", "period": "2019-2023"}
  ],
  "sections_found": ["工作经历", "教育经历", "在校经历"]
}
```

判读规则：小节标题独占一行（常与第一条经历同一视觉行，已单独拆出）→ 含时间范围的行是条目头（公司/职位/右对齐时间）→ 其下到下一条目头之间的行是描述与标签。

自带 CLI：`python extract.py --image runs\xxx.png` 或 `python extract.py --live`。

### 滚动读取（resume_reader.py）

- **只滚弹窗内部**：滚动点 = 正文区中心偏下（实测 x≈1187，落在 800..1574 内），不会把整个列表页滚走；
- **逐屏 OCR + 去重**：每滚一次识别一屏，只追加没出现过的文本行；每屏都跑一次结构化提取，再按（公司,时间）/（学校,时间）合并；
- **三种停止条件**：① 读到「教育经历」且后面还有内容；② 滚动后没有新内容；③ 达到 `max_steps`（默认 6 屏）；
- **调参入口**：`read_resume(..., max_steps=6, scroll_clicks=-3, settle=0.9)`；
- **安全**：滚动前同样要过输入闸门，光标没到位就抛 `InputBlocked`，不会在别处乱滚。

产物都在 `runs/`：`*.png` 原始截图、`*-annotated.png` 标注图、`*.json` 结构化结果。

## 已知限制（都是实测出来的）

1. **沙箱内不能注入输入**：`SendInput` 不报错但光标不动（UIPI / 进程完整性级别导致）。所以必须在你自己的终端里跑，不要通过受限代理跑。
   - 实测：低完整性（Low）进程的 `SendInput` **返回 1（被接受）但光标不动**，`SetCursorPos` 直接返回 False，`OpenProcessToken` 也打不开目标进程 —— 这是 Windows 的 UIPI 在拦低级别进程向中级别窗口注入。
   - 先用 `python diag_input.py` 看第一行的"当前进程完整性"：必须是 **Medium** 或更高。若显示 Low，说明这个终端被降权了（常见于从 IDE/沙箱/宿主应用里启动的终端），换从开始菜单直接打开终端，或以管理员身份运行。
   - 为此 `click()` / `scroll()` 都带**前置校验**：先移动，再读回光标位置，偏差超过 6px 就抛 `InputBlocked` 并中止，**绝不盲点**（否则可能在光标当前位置误点）。
2. **Esc 关不掉简历弹窗**：实测按 Esc 后仍是弹窗状态。已改为点右上角 ✕（`vision.close_button()`，用大「打招呼」按钮做锚点推算），点完会复检页面状态；失败才退到点遮罩、再退到 Esc。
3. **滚动加载**：`driver.py` 里 `scroll()` 用的是鼠标滚轮，滚多远、滚几次需要按实际列表高度调。
4. **浏览器缩放**不为 100% 时，上面所有像素值都要重算。
